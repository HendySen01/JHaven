## 4. 重要技术决策

- 短 WAV 静态自托管。构建比对目录、许可、哈希和 PCM 质量。沿用单一惰性 AudioContext，按需加载、原生循环、独立增益、单调计时。混音增益按目录上限预留数字余量。
- 新默认总音量 45%。原设备音量仍保留。定时表单默认建议 20 分钟，用户显式应用，刷新和退出页面不会恢复播放。
- 用户名小写唯一。密码使用 Node scrypt 与独立随机盐；MySQL 仅存随机令牌的 SHA-256 会话摘要。固定 7 天到期，退出及轮换即时撤销。
- 生产 Cookie 使用 Secure、HttpOnly、SameSite=Lax 与 __Host 前缀。写请求要求精确 Origin 和 JSON。基础健康与账户就绪分开。
- MySQL SQL 迁移含用户名、会话外键、过期索引与校验和记录，显式执行，UTC。真实测试实例为 MySQL 9.6.0。
- 新增直接依赖 mysql2 3.24.6（MIT）。Moodist、MDN、OWASP 用于研究。LeiBox、Impeccable、Trail of Bits Skills 为资料评估，未采用其源码或脚本。没有调用新的 Skills。

## 6. 最近一次测试结果

- A 阶段 `npm run check` 通过 74 项单元/API、格式、类型、Lint 和生产构建。Chrome 57/57，覆盖 375、768、1440px；十条真实 WAV 可混合，原有预设、加载失败和定时渐弱通过。数字检查无低于 −55 dBFS 的 50ms 静音窗，峰值最大 0.65。
- B 阶段在独立 MySQL 库两次 `npm run db:migrate`，两条迁移应用并确认幂等。有真实 MySQL 的 `npm run check` 为 82/82，Chrome `npx playwright test` 为 63/63。通过双用户身份隔离、过期、退出、重复用户名、生产 Cookie 属性及注册到退出的浏览器流程。
- `npm run dev` 前端 5173、API 专用 43002，页面和账户就绪代理为 HTTP 200。停止测试 MySQL 后账户就绪返回 503，WAV 仍为 200。全十轨连续循环观测 65.04 秒，采样峰值 0.1746，十条音轨仅解码一次，停止后活跃音源归零。完整命令与限制见 TESTING。
- 本轮无真实 .env、凭据或测试数据库纳入 Git。Git 检查包括新增文件及许可证。测试凭据和浏览器报告均在忽略目录。
