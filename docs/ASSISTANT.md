# 睡前助手

## Sprint 6C 意图理解与证据回答

DeepSeek 复用同一 SSE 请求，先接收本地检索的最多两条审核摘要和局限，以及用户本次输入。输出由四种结构组成，分别是证据回答、已审核功能建议、简短澄清和资料不足。模型可以理解未命中关键词的表达。管理员可继续使用 OpenAI 的审核措辞模式。

证据回答由模型编写贴合问题的短说明并指定一个证据位置。服务端要求该位置出现恰好一次，要求引用 ID 来自本次检索，再插入原审核摘要。前端显示该条来源及局限。自由说明仅接受短篇、无链接、数值和高风险措辞的内容。筛查是保守规则，无法证明所有自然语言说明的语义正确性，科学事实应以审核摘要和原来源为准。

所有推荐都通过共享的审核清单映射到已有的睡前状态、声音场景或练习，并由服务端补充理由。证据回答中的附带推荐还需要与本地规则一致。前端保留确认和手动启动。隐私及医疗分流先于模型调用，聊天仍只留在页面内存。结构或证据引用无效时回退到有本地标识的回复。网络异常保留重试和本地入口。

DeepSeek 新模式最多生成 192 个输出 Token，回复在服务端完整校验后才通过现有响应流发送。模型输入仍只含本次用户输入、固定指令和本次审核摘要及局限。沿用 0.01 美元的保守单次预留及现有限流。实际模型效果和费用需另行授权验证。

## Sprint 6B DeepSeek

核对日期 2026-11-18。配置 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL=https://api.deepseek.com` 和 `DEEPSEEK_MODEL=deepseek-flash` 后优先使用 DeepSeek。官方另有 `deepseek-v4-pro`，仅接受这两个当前模型及官方根地址或 `/v1`，防止凭据被转发到任意地址。旧模型名应在配置中更新。 [官方模型及价格](https://api-docs.deepseek.com/quick_start/pricing/)

复用 SSE 适配器，DeepSeek 请求使用 `max_tokens=96` 和 `thinking.type=disabled`。继续使用审核摘要及枚举措辞校验。模型尚不自由生成知识解释或识别新的推荐意图，站内意图与引用仍由已有确定性规则生成。 [接口](https://api-docs.deepseek.com/api/create-chat-completion/) [思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)

401/403、402、429、404/422 与服务器错误分别显示认证、余额、限流、模型配置和服务异常提示。用户可重试或使用本地知识。每请求超时 12 秒，最多三并发、每 IP 十分钟八次，最多三条本地上下文且模型只接收当次 400 字符输入。固定提示与输入保守预留 2400 token，输出上限 96。

新增 `AI_DAILY_BUDGET_USD=0.10`，每次模型请求按 0.01 美元预留，失败或取消不退回，同时受每日请求数限制。这是依据核对日价格设置的进程内保守额度，供应商调价或自定义 OpenAI 模型后须重新核算。重启、多实例会分别计数，实际财务上限仍须由供应商设置。此字段不代表已获付费测试授权。

## 使用与配置

Sprint 7 中，DeepSeek 证据回答先经过结构和来源校验，再显示简短释义和原审核摘要。模型在证据占位符后的补充不进入回复，避免复述摘要中的建议。公开界面区分服务状态检查失败、未启用模型和已经同意使用模型。停止或重试支持键盘操作，重试保留未发送的新草稿。

打开 `/assistant`。访客与登录用户均可使用审核知识、来源链接和站内推荐。选择“可将本次输入发送给 OpenAI”后，本页才会请求模型；可以取消同意、改用本地知识、停止、重试或清空。刷新、离开和登录身份切换时，浏览器清除对话。服务端不存聊天，不读取用户日记、身份或其他账户数据。

| 服务端环境变量           | 默认           | 用途                                                               |
| ------------------------ | -------------- | ------------------------------------------------------------------ |
| `AI_OPENAI_API_KEY`      | 空             | 仅放在服务端环境配置。空值只启用本地知识模式。                     |
| `AI_OPENAI_MODEL`        | `gpt-4.1-mini` | OpenAI Chat Completions 模型，需支持流式 JSON 输出。               |
| `AI_DAILY_REQUEST_LIMIT` | `120`          | 每个进程每 UTC 日的最大模型请求数，允许 0–500。设为 0 可关闭模型。 |

上线前检查供应商项目额度，使用独立的最小权限密钥。API 请求设置 `store:false`，供应商的留存政策另行适用。 [OpenAI 数据说明](https://developers.openai.com/api/docs/guides/your-data)

## 流程与边界

- `GET /api/assistant/status` 只返回供应商是否启用及知识库版本；`POST /api/assistant/chat` 校验 Origin、JSON、字段和长度，输出 NDJSON 流。前端不附带登录 Cookie，提供停止、重试、重新生成和本地回退。
- 规则层识别急症、医疗、隐私和越权内容，输出固定回应或匹配审核知识。遇到已识别的敏感内容、提示词注入和医疗问题时，不调用模型。关键词安全筛选可能漏判，因此请勿在聊天中粘贴私人正文或凭据。
- 响应先发送审核摘要。模型适配器用 SSE 获取两个固定表达 ID，服务端验证后将其转换为已审核的短句。模型无工具或数据库连接，回答不采纳模型提供的链接、医疗结论或任意动作。引用直接来自版本化知识库。
- 确定性规则只允许现有雨夜、海岸、微风场景及四项成人放松练习。前端单独确认后才更新“今晚状态”并跳转；播放和练习启动仍由用户控制。
- 站内规则使用最近三条输入，模型仅接收本次输入。边界包括每条最多 400 个 JavaScript 字符单元、每 IP 每十分钟八次、每进程最多三个并发模型请求、12 秒模型超时及每次最多 96 个输出 token。失败和主动停止也消耗该次调用额度，API 不自动重试。进程重启会清空计数，多实例须由网关或供应商额度统筹。当前为请求量限制，费用也取决于供应商价格、输入及实例数量。
- 测试仅使用模型替身和模拟 SSE。本轮真实供应商请求数为 0，未发生真实 API 调用费用。模型上线需另外验证密钥可用、模型兼容、代理流式转发和供应商预算。
