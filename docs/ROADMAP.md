## Sprint 1：沉浸式 UI、交互与状态管理（当前）

- [x] 品牌、标语、欢迎语、真实导航与开始放松入口。
- [x] 今晚四种状态与可解释建议；状态只存内存。

- [x] 最终检查与 375/768/1440px 浏览器验收归档：35 项单元/API、30 项 E2E、类型/Lint/构建通过。

## Sprint 2：环境音引擎

1. 先选权利清晰的雨/海浪/风素材或明确标注的自主合成方案，登记每项来源。
2. 设计可释放的 Web Audio 引擎；实现手势启动、多轨独立音量、预设、播放/暂停/主动停止。
3. 加入定时和渐弱、恢复失败提示、后台/锁屏策略与设备回归。
4. 实现四种今晚状态及可解释规则推荐，允许用户自行改选。

完成条件：朋友能真正播放和停止；无假音轨、无未处理播放拒绝；资源回收与移动设备验证有记录。

## Alpha 2：身份与私人日记

1. 确定会话方案，建立 MySQL 迁移、最小权限连接与备份恢复流程。
2. 实现注册/登录/登出、Cookie/CSRF/限流、安全密码哈希和服务端验证。
3. 实现日记增删改查、可选字段、本地日期与时区、有限分页和简单趋势。
4. 实现自定义场景/偏好持久化；验证每类私人资源的跨用户隔离。

完成条件：两个真实测试账户无法互访资源；能删记录与账号；恢复演练、隐私说明与错误场景通过。

## Alpha 3：温和引导与朋友内测

提供经过内容审核、可暂停/跳过/结束的非临床放松内容；按实际需求存必要会话信息。完善主入口、设备兼容性、键盘与触屏体验，再邀请少量朋友；不默认收集追踪数据。

完成条件：核心流程真实可用；没有高优先级隐私或数据隔离缺陷；文案边界清楚；部署、回滚、删除与反馈渠道明确。

## Beta

根据真实反馈修复稳定性、后台行为与易用性，完善知识来源、可访问性、备份、导出和用户自助管理。性能目标须基于可复现测量建立，不提前虚报指标。

## V1.0 与长期产品化

明确运维责任、数据保留周期、内容审核、依赖维护和发布流程。在核心功能稳定后，评估规则引擎 + 审核知识库 + AI；先设计授权与发送边界，再选择 SDK。AI 不成为非 AI 功能的强制前提。
